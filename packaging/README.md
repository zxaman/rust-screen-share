# Building the preview packages

Both packages embed the single HTML document generated by `bundle.py` from `apps/desktop`. Fonts, artwork, icons, license notices, JavaScript and CSS are included. No network service is required. Run the commands from the repository root.

## Windows x64 (PowerShell)

Use Python 3 and a stable x64 Rust toolchain (including its native linker).

```powershell
python packaging/bundle.py dist/workspace.html
$env:NODEPORT_HTML = (Resolve-Path dist/workspace.html).Path
rustc --edition=2021 --target x86_64-pc-windows-msvc -C opt-level=s -C panic=abort apps/windows/main.rs -o dist/Nodeport-Windows-x64.exe
```

The Rust GUI launcher writes its embedded HTML to `%LOCALAPPDATA%\Nodeport Preview\workspace.html` and opens it with the system HTML handler. It needs no administrator access. It does not install a background agent. To remove it, delete the executable and that folder. Clear demo data in the browser separately if needed. For cross-compilation use the `x86_64-pc-windows-gnu` Rust target and a compatible MinGW-w64 linker.

## Android (Linux/macOS)

Install a JDK (17 recommended), Python 3, Android SDK Platform 35 and SDK Build Tools 35.0.0. Set `ANDROID_HOME`, add your JDK's `bin` to `PATH`, and supply a keystore that **you** control. If you need a new key, generate one outside the checkout and keep its password and backup private:

```sh
keytool -genkeypair -keystore "$HOME/nodeport-preview.p12" -storetype PKCS12 \
  -alias preview -keyalg RSA -keysize 3072 -validity 3650
export NODEPORT_KEYSTORE="$HOME/nodeport-preview.p12" NODEPORT_KEY_ALIAS=preview
./packaging/build-android.sh
```

The output is `dist/Nodeport-Android.apk`. This app uses a local WebView, with no Android permissions, remote content, or JavaScript-to-native bridge. Keep Android System WebView updated. Android requires the same signing key for in-place updates: uninstall a differently signed preview first (this erases its demo state). The published preview key is disposable, not a production signing identity.

## Verification

On an actual target, open the package, pair a simulated device, grant a capability, end the session, and relaunch to check persistence. `apksigner verify --verbose --print-certs` verifies the APK's signature; it does not test runtime behavior. For distribution, publish a SHA-256 manifest along with both binaries. Do not publish a keystore or signing password.
